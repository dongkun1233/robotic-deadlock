# Frozen comparison: FCFS anchor, 72 evaluations, five seeds

Protocol fixed on 2026-10-31 (Korea time), before this comparison's optimization and before opening the untouched final test. This is a new protocol, not an extension of old saved trials. Simulators and four feature definitions are frozen at v2. No new feature, rule, model mask, or validation-selected algorithm is introduced.

- Fixed manifest: existing 80 training / 40 development-validation / 80 final-test scenarios; SHA256 90c2eb4e9a56d8ce2d8a2dea444190e05e613c6a565894636448e802f29730f6.
- Policies: feasible FCFS, and the full four-feature score optimized by random search, GP-LCB BO, or projected PSO. Compare all three; do not select a favorable algorithm after validation.
- Seeds: 101, 202, 303, 404, 505. All three methods receive the same six initial vectors within each seed. The first vector is waiting=1, others=0 (FCFS); the other five are seeded random normalized vectors.
- Budget: exactly 72 objective evaluations per method/seed, INCLUDING all six initial candidates. 1,080 evaluations × 80 training cases = 86,400 episodes. No early stopping or adaptive budget increase. PSO uses six particles and eleven complete updates after initialization. Its inertia depends on total budget, so its first 24 evaluations need not match an old 24-evaluation run.
- Objective and safety checks unchanged: completion prioritized, then mean capped makespan. Select the earliest best training objective for each method/seed. The common anchor ensures the best training objective cannot be worse than training FCFS (up to numeric tolerance); it does not guarantee held-out improvement.
- Five seed jobs may run concurrently, with one process per seed and one BLAS thread each. Each repeats its own FCFS baseline; the consolidated dataset retains one identical baseline. Actual baseline compute is five × 80 episodes, not one × 80. Timing under concurrent load is descriptive; no algorithm-speed claim will be made from it.
- Validation: evaluate all 15 fitted policies and FCFS on the existing 40 development cases. These cases have been inspected before; they are not an independent final test. Do not change any settings, drop seeds, or select models based on their scores.
- Final test: after training/validation integrity checks pass, evaluate all 15 fitted policies plus FCFS once on the 80 untouched cases (1,280 episodes). Freeze the selected weights and save their digest before test execution. Never retune on these outcomes. If test execution exposes a correctness bug, invalidate the test as independent and disclose that a new test set would be needed.
- Report all seeds, completion counts, makespan, mean/max wait and spawn delay. Main paired contrasts: each of the three methods vs FCFS. Secondary contrasts: BO vs random, PSO vs random, BO vs PSO. Average paired optimizer seeds within each scenario; stratify scenario resampling by the four traffic conditions. Also report a two-way bootstrap resampling optimizer seeds and scenarios, explicitly approximate with only five seeds. Nominal 95% intervals are not simultaneous intervals. For the three primary contrasts, report Holm-adjusted two-sided scenario sign-flip permutation p-values (100,000 draws, fixed seed), conditional on fitted seeds and exchangeability assumptions. Secondary contrasts remain exploratory. A nonsignificant difference is not equivalence.
- Limits: one 2×3 topology and one demand generator, finite batches, node motion with conservative reservations, no rotation/service physics. No real-warehouse or universal deadlock-freedom claim. The new experiment tests optimizers on the full model; it does not itself confirm four-feature necessity.

Reproduce training with run_multicross_anchored_search.py --simulator v2, then audit the consolidated folder. All source hashes and environment versions are recorded. Existing historical runs remain separate.
