# 현재 레이아웃의 초기 가중치와 하류 혼잡도 진단

검토일: 2026-11-01. 모든 새 관측과 시뮬레이션은 기존 학습 80개만 사용했다. 이미 사용한 검증·최종 테스트를 새 정책 평가에 다시 사용하지 않았다. 새 독립 테스트는 아직 만들거나 실행하지 않았다.

## 초기값 질문에 대한 확인

세 가지를 구분해야 한다.

1. v2 시뮬레이터에서 가중치를 생략하면 쓰는 임시 기본값은 waiting=1, maneuver=-0.5, exit=-0.5, path=-0.5다. 이것은 단독 heuristic 동작 확인용 기본값이며 최근 BO/PSO의 공통 초기값이 아니다.
2. 최근 72회·5시드 비교의 초기 6개는 FCFS [1,0,0,0]와 시드별 무작위 단위 벡터 5개였다. 예전 single/double-cross Basic 최적값을 그대로 주입하지 않았다.
3. 현재 multicross 레이아웃과 feasible-first 규칙에서 이미 학습한 좋은 가중치는 warm-start 후보로 재활용할 수 있다. 현재 레이아웃에 맞는 가중치를 전혀 찾지 않은 상태는 아니다.

이번에는 기존 random-search 학습 기록 360평가에서 학습 목적함수만으로 좋은 후보를 뽑고, 서로 지나치게 비슷한 방향을 피하도록 cosine similarity < 0.98인 다섯 벡터를 선택했다. FCFS 벡터를 더해 공통 초기 후보 6개를 만들었다. 이는 향후 초기화안이며 이 초기화안으로 BO/PSO를 다시 실행한 결과는 아니다. 최적 초기화라는 주장도 아니다.

가장 낮은 Basic 학습 평균을 가진 후보는 시드404, 평가21이었다.

| 변수 | 가중치 |
|---|---:|
| waiting | +0.6547162954 |
| maneuver | +0.0697006401 |
| exit_competition | +0.7468916155 |
| path_conflict | -0.0929586360 |

이 후보의 학습 평균은 83.4750, FCFS는 84.1750이다. 학습에 사용한 80개에서 고른 값이므로 보편적 변수 중요도나 새 테스트 성능을 뜻하지 않는다. 양의 공통 배율은 순위를 바꾸지 않으며, 변수 간 상관·정규화 때문에 각 가중치를 독립적인 중요도로 해석할 수도 없다. 최근 BO는 이미 학습 최솟값 83.3875까지 찾았으므로, Basic 후보를 초기값으로 쓰면 BO의 기존 최종 결과보다 자동으로 좋아질 것이라는 근거도 없다.

공정한 비교에서는 무작위 연속 탐색을 포함한 모든 방법에 같은 초기 후보 집합을 줘야 한다. 이 집합을 만드는 선행 360평가/28,800개 시뮬레이션의 비용도 공개해야 한다. 비용은 이미 과거 실행에 지출한 것이며 이번 후보 추출 자체에는 새 시뮬레이션이 없었다. '무작위 72회'와 '선행 무작위 360회 + BO 72회'를 동일 총예산 비교로 제시하지 않는다. 공통 전처리 비용을 포함한 비교 또는 이미 존재하는 후보 집합에 조건부인 후속 탐색으로 구분한다.

새 변수까지 포함한 5차원 정책으로 바뀌면 이 네 변수 가중치에 새 계수 0을 붙인 후보가 기존 동작을 보존하는 출발점이다. 4차원 후보를 새 변수를 이미 학습한 가중치라고 부르면 안 된다.

## 정체 원인 관측

기존 v2 함수의 진입 판단과 대기 증가 지점을 sys.settrace로 관측했다. 시뮬레이터의 선택·이동 상태를 바꾸지 않았다. FCFS와 위 Basic 후보 각각 학습 80개를 실행하고, 추적을 끈 동일 실행 160개와 차량별 결과 및 진입 로그가 일치함을 확인했다. 대기 증가의 합도 각 AGV 최종 대기 합과 일치했다.

FCFS의 차량-단계 대기 합 41,294 중 다음과 같이 분류됐다. 조건이 겹치면 용량 → 점유 → 예약 순서로 분류한 기술적 원인이다. 서로 독립된 인과 효과나 실시간 창고의 병목 점유율로 해석하지 않는다. 출발 전 지연은 여기에 포함하지 않고 별도로 기록했다.

| 대기 분류 | 차량-단계 수 |
|---|---:|
| 다음 셀이 현재 점유되어 이동하지 못함 | 23,075 |
| 진입 시 예약할 구역 경로/첫 출구 셀이 점유됨 | 9,761 |
| 진입 경로/첫 출구 셀이 예약됨 | 6,132 |
| 구역 진입 용량이 찼음 | 2,326 |
| 다른 진입 순서·동일 목적 셀·기타 예약 대기 | 0 |

가장 오래 걸린 사례는 train_c4_005(48대 동시 출발 예정, 117단계, 총 대기 1,155 차량-단계), train_c4_013(116단계), train_c3_001(115단계)이었다. 초기 출시와 무방해 경로 길이에서 얻는 하한과의 차이는 기록했지만, 그 차이 전부를 정책으로 제거 가능한 손실로 주장하지 않는다. 현재 이동 규칙은 같은 단계에 앞차가 떠나도 점유 셀에 뒤차가 들어가지 못하는 보수적인 노드 모델이다.

## 하류 혼잡도 정의와 실제 관측 가능성

현재 교차로의 core를 나온 첫 셀부터, 고정 경로상의 다음 교차로 대기점 또는 최종 출구까지를 하류 구간으로 정의했다. 첫 출구 셀과 다음 대기점을 포함하며 다음 core는 포함하지 않는다. 현재 활성 차량의 점유 셀과 현재 예약 셀의 합집합을 구간 셀 수로 나눈 값이다. 중복 점유·예약을 두 번 세지 않고 미래 출발·미실현 교통량을 읽지 않는다.

FCFS 학습 기록에서 실제 진입 가능한 후보가 둘 이상인 시도는 1,950회였다. 이 중 하류 점유율이 다른 시도는 834회(42.8%), 최소 하류 점유율을 고르면 FCFS와 다른 후보를 고르는 시도는 574회였다. 후보가 정확히 두 대인 1,561회 중에서도 551회에서 값이 달랐다. Basic 후보에서는 1,930회 중 857회에서 값이 달랐다.

이는 기존 exit_competition과 다른 정보를 관측할 수 있다는 근거다. 반복된 의사결정 시도이며 독립 표본이 아니다. 값 차이·선택 차이 자체는 성능 개선의 증거가 아니다.

## 먼저 확인한 단순 정책: 성능 개선은 확인하지 못함

안전 예약과 feasible-first 진입 규칙을 그대로 두고, 가능한 후보 중 하류 점유율이 최소인 차량을 선택했다. 동률이면 기존 대기 도착 시각/ID 순서를 썼다. 회전·이동·서비스 시간 등의 모델은 바꾸지 않았다. 비교의 FCFS와 기존 4변수 정책은 원본 v2와 차량별 결과가 정확히 같음을 확인했다.

| 학습 80개 정책 | 평균 완료 단계 | 평균 차량 대기 | 관측 최대 대기 |
|---|---:|---:|---:|
| FCFS | 84.1750 | 12.5667 | 66 |
| 기존 4변수 Basic 학습 최적 후보 | 83.4750 | 12.5266 | 67 |
| 하류 점유율 최소 우선 | 85.0625 | 12.3505 | 69 |

하류 최소 우선은 FCFS보다 15개에서 빠르고, 33개에서 같고, 32개에서 느렸다. 전체 완료시간은 +0.8875단계로 나빠졌다. 평균 대기는 약간 줄어도 마지막 차량의 완료와 최대 대기는 악화될 수 있다는 관측이다. 목적함수인 makespan 개선 정책으로 채택하지 않는다.

## 작은 사전 고정 학습 그리드

대기를 무시한 교체 효과와 정보 추가 효과를 구분하기 위해, 실행 전 파일에 두 점수식과 계수 집합을 저장했다. 계수 lambda는 0, 0.25, 0.5, 1, 2의 다섯 값만 사용했다. 총 800회이며 검증/테스트는 실행하지 않았다.

- waiting-normalized - lambda × downstream occupancy
- 기존 Basic 최적 4변수 점수 - lambda × downstream occupancy

lambda=0의 차량별 결과는 원본 FCFS/4변수와 같았다. 모든 실행이 완료됐다.

| lambda | waiting+하류 평균 단계 | 기존 4변수+하류 평균 단계 |
|---|---:|---:|
| 0 | 84.1750 | 83.4750 |
| 0.25 | 84.1500 | 83.5250 |
| 0.5 | 84.1500 | 83.6250 |
| 1 | 84.0375 | 83.6875 |
| 2 | 84.0375 | 83.8750 |

waiting과 조합하면 FCFS 대비 학습 차이가 최대 -0.1375단계였지만, 이 작은 그리드에서 기존 4변수 후보에 양의 하류 페널티를 추가한 경우는 모두 평균이 악화됐다. 점유율이 관측 가능하다는 이유로 자동 채택할 수 없다. 기존 네 가중치까지 공동 재최적화한 실험은 아니므로, 모든 5변수 정책의 무효를 증명한 것도 아니다. 이후 무제한으로 계수를 바꿔 유리한 결과를 고르지 않는다.

## 현재 판단

1. 현재 레이아웃/규칙에 맞는 warm-start 후보 집합은 준비했다. 공통 후보와 선행 비용을 명시한 후속 탐색에 사용할 수 있다.
2. 하류 점유율은 관측 가능하지만, 이번 학습 진단에서 기존 정책보다 좋아진다는 근거는 얻지 못했다. 핵심 개선 변수로 채택하거나 논문 기여라고 주장하지 않는다.
3. 다음 실험을 정한다면 초기값 효과를 같은 후속 예산에서 따로 비교하거나, 정체의 누적 대기/접근 통로 부담을 더 잘 표현하는 지표를 검토할 수 있다. 이번 결과만으로 어느 방향도 성공한다고 말할 수는 없다.
4. 새 정책을 확증할 때에는 평가 전에 생성 조건을 고정한 새 테스트가 필요하다. 이번 작업에서는 독립 테스트 성능 주장을 추가하지 않았다.

원시 후보 관측은 candidate_observations.csv.gz, 모든 시나리오 및 계수 실행 결과는 각 outputs 폴더에 보존했다. 관측·정책 코드와 초기 후보 생성 코드도 함께 저장한다. 원본 v2 및 이전 최종 테스트 결과는 수정하지 않았다.
