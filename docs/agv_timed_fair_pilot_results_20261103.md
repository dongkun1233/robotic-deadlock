# 팀원 FairBO·FairPSO 방식의 다중 교차로 예비 학습

동일 가중치에 보호 규칙을 추가한 비교와, 보호 규칙을 켠 상태에서 재학습한 비교를 분리했다. 최종 테스트는 사용하지 않았다.

## 이번 예비 결과의 핵심

개발 48개에서 FCFS 평균 완료시간은 140.352초, 무보호 BO는 140.618초, 무보호 PSO는 140.618초였다. 보호 포함 재학습도 FCFS보다 평균 완료시간이 짧지 않았다. 한 시드의 개발 결과이며 FCFS의 확정적 우월성이나 BO/PSO의 무효성을 뜻하지 않는다.

BO와 PSO 각각에 같은 가중치로 20초 보호를 적용하면 48개 중 47개는 완료시간이 같고 1개는 길어졌다. 평균 차이는 +0.160833초이며 탐색적 미보정 부트스트랩 구간은 [0.000000, 0.482500]초다. 평균 시나리오 최대 누적 진입대기는 각각 약 0.144초 감소했다. 40초 보호는 이 무보호 최선 가중치들의 개발 궤적에서 선택을 바꾸지 않았다. 보호 조건에서 다시 학습한 가중치는 다른 궤적을 만들 수 있으므로 이 무개입 관측을 모든 40초 정책에 일반화하지 않는다.

이 결과는 팀원의 보호 규칙을 넣으면 현재 다중 교차로에서도 완료시간이 개선될 것이라는 기대를 지지하지 않는다. 다음 본 학습은 기존에 고정한 확대 자료·동일 예산·다섯 탐색 시드 설계를 유지하며, 이 예비 결과로 개발 자료를 다시 학습에 쓰거나 유리한 임계값을 새로 선택하지 않는다. 최종 독립 테스트와 변수 제거 재학습은 아직 완료되지 않았다.

## 설정

학습 48개·개발 48개, 다중 교차로, 탐색 시드 101 하나, 방법별 30회 평가, 같은 초기 여섯 후보를 사용했다. 무작위 탐색도 같은 예산의 대조군이다. 물리 조건·진입 가능 후보·안전 검사는 기존과 같다.

팀원 원본의 FairBO/FairPSO는 BO/PSO가 찾은 기존 가중치에 20초·40초 장기 대기 우선권을 더하는 방식이다. 본 실험은 그 동일 가중치 비교를 재현하고 보호 상태 재학습을 추가했다. 팀원 별도 Improved 학습의 최대 대기 벌점은 섞지 않았다. 최적화기는 우리 기존 GP-LCB/투영 PSO를 고정하여 규칙 효과를 분리했으므로 팀원 저장소 전체 실행을 그대로 재현한 결과는 아니다.

## 검증과 해석 범위

예산상 목적함수 호출 270회. 완료된 캐시 기록 12144개 중 직접 시뮬레이션 9675개, 보호 임계값에 도달할 수 없음을 확인한 재사용 2469개다. 재사용 24개를 직접 재실행해 지표·궤적 일치를 확인했다.

재사용 근거: 완료된 무보호 궤적에서 모든 차량의 누적 진입 대기가 T보다 작으면, 각 지역 대기는 그 누적값 이하이므로 보호 T가 어느 시점에도 개입할 수 없다. 경계에 충분한 여유가 있을 때만 사용하며 미완료 궤적은 재사용하지 않는다. 이 비용 절감과 별개로 모든 방법의 초기 여섯 관측은 30회 예산 안에 포함한다.

이전 초기값 보정 및 예비 학습 비용은 공통 선행 비용이다. 이번 방법별 30회가 처음부터 모든 초기값을 생성하는 전체 비용이라는 뜻은 아니다. 반복 정책 평가나 재사용을 독립 시나리오 수에 더하지 않는다.

한 시드·제한된 탐색 횟수의 개발 실험이다. 평균 완료시간과 긴 대기의 상충을 함께 보며, 대기만 줄었다고 전체 성능이 개선됐다고 부르지 않는다. 보호 규칙은 안전상 진입 불가능한 AGV를 강제로 보내지 않고, 이 임계값 자체가 최대 대기 상한을 보장하지도 않는다.

## 실행 환경 및 저장 복구

현재 환경에서 관련 검사 32개와 하위 검사 3개가 통과했다. 실행 도중 환경 연결이 끊긴 뒤 프로세스 종료를 확인하고 체크포인트에서 재개했다. 집계 검사는 일부 캐시의 불완전한 접두 기록을 발견했다. 38개 캐시에서 누락된 시나리오 행 137개를 같은 고정 입력으로 복구하고 상태를 완료로 확정했다. 복구 후 270개 학습 목적함수 값 전부가 저장된 trial 값과 절대 오차 1e-10 이내에서 일치했다. trial·가중치·선택 결과는 변경하지 않았다. 구체적인 파일과 행은 cache_recovery.json에 남겼다.

최종 보존 캐시 12,144건은 모두 완료됐고 안전 검사를 통과했다. 이 중 직접 실행 기록 9,675건과 임계값 미도달 근거의 재사용 2,469건이 있으며, 재사용 표본 24건을 직접 실행해 지표와 궤적 일치를 확인했다. 실행 손실 전에 계산했으나 보존되지 않은 시도의 원래 CPU 비용은 알 수 없다. audit.json의 CPU 합계는 보존 기록의 합계이며 전체 재시도 포함 계산 비용이 아니다. 복구 행 수 역시 손실된 전체 실행 시도 수와 같다는 뜻이 아니다.
