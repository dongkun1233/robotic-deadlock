# FCFS 공통 초기값·72회 평가·5시드: 고정 프로토콜 결과

프로토콜은 학습과 최종 테스트 실행 전에 GitHub 커밋 `30dce7e60b0360bbbb59388b1b1597f52f8943f6`으로 고정했다. 최종 평가 코드와 테스트도 최종 실행 전에 커밋 `a746320c6528e1f8bf7b4714208f7f33fa3d6140`에 보존했다. 학습 80개, 개발 검증 40개, 처음 사용하는 최종 테스트 80개의 역할을 유지했다. 검증 결과로 방법·모델·가중치를 골라 바꾸지 않고 세 방법과 다섯 시드를 모두 최종 평가했다.

## 완료 및 무결성

- 학습: 3방법 × 5시드 × 72평가 = 1,080평가, 목적함수 시뮬레이션 86,400회. 모든 후보 완료, 동일 초기 6개 및 예산 확인, 제거된 실패 기록 없음.
- 초기 후보 중 waiting=1, 나머지=0의 FCFS 가중치를 공통 포함했다. 15개 방법/시드 조합 모두 최종 학습 최솟값이 FCFS 84.1750 이하임을 확인했다.
- 다섯 시드는 병렬 프로세스로 실행했다. 각 프로세스가 FCFS 80회를 실행했으므로 실제 별도 기준선 계산은 400회다. 통합 결과에는 동일한 기준선 80행만 보존했다. 병렬 실행 시간으로 알고리즘의 속도 우위를 주장하지 않는다.
- 개발 검증: 16정책 × 40개 = 640회. 중복 0, 미완료 0.
- 최종 테스트: 16정책 × 80개 = 1,280회. 중복 0, 미완료 0. 테스트 실행 전에 정책 가중치와 digest를 frozen_selection_before_test.json에 저장했다.
- 안전성 및 탐색/통계 회귀 테스트 8개 통과. 테스트 성공은 전역 안전성·교착 방지 정리가 아니다.

## 평균 완료 단계

최적화 방법은 시드 101/202/303/404/505의 평균이다. 학습 열은 각 시드에서 학습 목적함수로만 선택한 최저점이며, 검증/테스트에는 해당 고정 가중치를 적용했다. 행의 순서는 성능 순위가 아니다.

| 방법 | 학습 평균 | 개발 검증 평균 | 최종 테스트 평균 |
|---|---:|---:|---:|
| FCFS | 84.1750 | 84.7000 | 83.2125 |
| 무작위 탐색 | 83.5375 | 84.5050 | 83.1200 |
| BO | 83.4575 | 84.6250 | 83.1175 |
| PSO | 83.4925 | 84.7600 | 83.1575 |

BO와 PSO 모두 학습 최솟값은 개선되었다. 그러나 이는 독립 테스트 개선을 보장하지 않았다. 최종 테스트에서 BO와 무작위 탐색의 평균 차이는 -0.0025단계로 매우 작다. 이 표에서 BO를 숫자상 1위라고 소개하며 알고리즘의 우월성을 주장하는 것은 부적절하다. 서로 다른 split의 절대 평균을 비교해 정책 개선량으로 해석하지 않는다.

## 사전에 정한 짝지은 비교

음수는 앞 방법의 단계가 더 적다는 뜻이다. 고유 테스트 시나리오 80개를 비교 단위로 삼고, 먼저 같은 시나리오 안에서 다섯 최적화 시드의 차이를 평균했다. 10,000회 층화 bootstrap으로 시나리오 불확실성을 계산했다. 추가로 시드와 시나리오를 함께 복원추출하는 two-way bootstrap을 제시했다. 다섯 시드뿐인 후자는 근사치이며 최적화기의 전체 불확실성을 완벽하게 추정하지 않는다. 아래 구간은 명목 95% 구간이며 동시 신뢰구간이 아니다.

| 비교 | 평균 차이 | 시나리오 95% 구간 | 시드·시나리오 two-way 95% 구간 |
|---|---:|---|---|
| 무작위 - FCFS | -0.0925 | [-0.6950, +0.5175] | [-0.7600, +0.5950] |
| BO - FCFS | -0.0950 | [-0.7975, +0.6050] | [-0.8150, +0.6225] |
| PSO - FCFS | -0.0550 | [-0.6600, +0.5575] | [-0.7025, +0.6351] |
| BO - 무작위 | -0.0025 | [-0.2400, +0.2125] | [-0.4400, +0.4275] |
| PSO - 무작위 | +0.0375 | [-0.1325, +0.2150] | [-0.2325, +0.3325] |
| BO - PSO | -0.0400 | [-0.2550, +0.1625] | [-0.4375, +0.3600] |

세 주요 FCFS 대비 비교는 100,000회 양측 짝지은 sign-flip 검정에 Holm 보정을 적용했으며 보정 p값은 모두 1.0이다. 검정은 고정된 학습 결과와 시나리오 차이의 부호 교환가능성 가정에 조건부다. 나머지 세 비교는 탐색적이다. 모든 구간이 0을 포함하고, 최적화 방법의 확실한 개선 근거를 얻지 못했다. 이를 동등성의 증명이나 모든 레이아웃에서의 FCFS 최적성으로 바꾸어 해석하지 않는다.

## 해석과 이후 연구의 범위

이전 24회·3시드·무작위 초기값 비교에서는 PSO의 일부 학습 결과가 FCFS보다 나쁘기도 했다. 공통 FCFS 초기값과 평가 예산/시드 확대를 함께 적용한 이번에는 그 문제를 없앴다. 그러나 초기값과 예산을 동시에 바꾸었으므로 결과 차이를 한 요소만의 효과라고 추정할 수는 없다. 동일한 72회 프로토콜 내 학습 진행 기록은 6/12/24/48/72회 지점에서 확인할 수 있다. PSO의 관성은 전체 예산에 따라 달라지므로 예전 24회 실행을 새 실행의 앞부분과 동일하다고 가정하지 않는다.

현재 지지되는 결론은 '이 연결 교차로·수요 생성기·진입 규칙·네 변수의 점수식에서는, 더 큰 공정 비교에서도 복잡한 최적화의 추가 이득이 명확하지 않았다'이다. 네 변수 모두가 필수라는 주장도 이 실험으로 확인되지 않았다. 이전 제거 실험은 개발 검증 결과이므로 최종 테스트의 변수 유효성 증거로 소개하지 않는다.

현재 최종 테스트 80개는 이제 평가에 사용했다. 이후 하류 혼잡도 등 변수나 정책을 수정하면 이 세트는 이미 본 자료가 된다. 새로운 확증 평가에는 변경 전에 별도로 고정한 새 테스트 세트가 필요하다. 향후 개발 결과를 기존 최종 테스트에서 반복 비교하며 독립 테스트라고 부르지 않는다.

물리적 창고의 실증, 연속 유입, 회전/서비스 시간, 다양한 토폴로지, 전역 교착 방지에 대한 보장은 여전히 범위 밖이다. 따라서 한 번의 공정 비교로 연구 전체가 '완전히 타당해졌다'고 표현하지 않는다.

## 파일과 재현

- 학습 원시 86,400행은 outputs/multicross_anchored_train_v1/training_episode_results.csv.gz에 모두 보존한다. audit_multicross_training.py가 개별 평가 CSV를 복원하고 목적함수를 재계산한다.
- outputs/multicross_anchored_validation_v1에는 개발 검증과 학습 진행 기록이 있다.
- outputs/multicross_anchored_test_v1에는 동결 가중치, 테스트 원시 1,280행, 모든 시드, 비교 통계와 감사 파일이 있다.
- 검증 보고기의 기존 'three fitted seeds' 문구만 다섯 시드에 맞게 정정했다. 수치 계산은 처음부터 checkpoint의 다섯 시드를 사용했으며 이 정정으로 가중치 선택이나 테스트 계산은 바뀌지 않았다.

각 시드별로 run_multicross_anchored_search.py --simulator v2 --seeds SEED를 실행한 뒤 merge_multicross_anchored_seeds.py, audit_multicross_training.py, run_multicross_anchored_validation.py 순서로 진행한다. evaluate_multicross_anchored_test.py는 고정 프로토콜과 가중치·소스 hash를 확인하고 실행한다. 기본 순차 학습도 가능하며, 정확한 환경/소스/manifest bytes 일치가 resume 조건이다.
