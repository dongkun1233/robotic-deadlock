# 팀원 설정 검토와 공통 물리시간 모델 준비

검토일 2026-11-02. 대상 저장소 poketmon2004-droid/robotic-deadlock-fairness, 기본 브랜치 feature/realistic-agv-fairness, 고정 커밋 f7240040f2b88a3a02462c3c78eb68c66a4cc9a0. 공개 코드의 정적 검토이며 팀원의 전체 실험이나 README 성능 수치를 재실행·검증했다는 뜻은 아니다.

## 확정한 사용자 조건

- 차체: SHARP XF Type A, 길이 0.825m·폭 0.480m·높이 0.190m, 최대 주행속도 1m/s를 참고.
- 모든 차량 기본 주행속도 0.8m/s. 직진 가감속 생략.
- 차체만 대상으로 하고 화물 외형·견인 대차·배터리·적재 작업은 포함하지 않는다.
- 제자리 회전, 최대 각속도 1rad/s, 각가속도/감속도 크기 2rad/s², 회전 시작과 끝은 정지.
- 격자/단방향 차로 1.5m, 양방향 차로 3m, 우측 통행, 다중 교차로 2×3, 구역당 최대2대와 경로·점유 예약 검사를 함께 적용.
- 주지표는 예정된 작업 묶음의 전체 완료시간(makespan, 초). 보조지표는 차량별 평균·95백분위·최대 대기, 출발 지연, 완료율 및 계산 비용.
- 공통 시각 원점은 시나리오의 t=0. 정책마다 첫 출발 차량 시각을 원점으로 다시 잡지 않는다.

안전 여유는 사용자가 아직 수치를 지정하지 않았다. 준비한 설정에는 0.10m를 제안 연구 가정으로 명시했다. 차체 중심 회전과 외접원 근사 역시 연구 가정이다. 실제 제조사 안전거리나 실제 회전 중심을 확인한 값이 아니다. 민감도 후보는 여유 0.05/0.10/0.20m이며, 공간 엔진을 확정할 때 조합의 기하학적 실행 가능성을 확인해야 한다.

## 참고할 수 있는 구현

[realistic_cross_simulation.py](https://github.com/poketmon2004-droid/robotic-deadlock-fairness/blob/f7240040f2b88a3a02462c3c78eb68c66a4cc9a0/rware/realistic_cross_simulation.py)는 in_flight에 이동 중 상태와 완료 tick을 기록한다. 이동 동안 출발 셀을 유지하고 도착 셀을 예약하며, 구역에서 나가는 이동이 끝나기 전에는 진입 허가를 해제하지 않는 부분은 공통 엔진 설계에 참고할 가치가 있다.

[analyze_step96_queue_fix.py](https://github.com/poketmon2004-droid/robotic-deadlock-fairness/blob/f7240040f2b88a3a02462c3c78eb68c66a4cc9a0/analyze_step96_queue_fix.py)의 FixedQueueModel은 이미 허가받은 차량을 다시 대기열에 넣지 않는다. 이 중복 등록 방지도 옮겨야 할 일반 수정이다. 정책 효과와 함께 묶어 성능 향상이라고 부르지 않는다.

## 현재 설정과 다른 점

| 항목 | 공개 코드에서 확인한 내용 | 새 공통 기준 |
|---|---|---|
| 시간 진행 | step()마다 next_tick=step_count+1, ceil(duration/dt) | 실제 동작 완료 시각으로 진행하는 이벤트 방식 |
| 설정 기본값 | AGVPhysicalConfig: 셀1m·속도1m/s·고정회전지연1s | 사용자 조건의 셀1.5m·속도0.8m/s·각속도/각가속도 |
| 주요 실행 스크립트 | 셀1.5m·속도1m/s, 회전식은 별도 분석 클래스에 있음 | 중앙 설정을 모든 실행에서 사용 |
| 회전 | TurnModel의 angle/omega, angular acceleration 없음 | 정지→가속→감속→정지 프로파일 |
| 차량별 속도 | IndividualSpeedModel에서 기본1m/s, 일부 실험0.8~1.2m/s | 첫 기준선은 모두0.8m/s, 연구 기종 최고1m/s 초과 금지 |
| 차체 기하 | 공통 physical config에 길이·폭·회전 외접 범위 없음 | 차체 외접원+명시한 여유를 공간 예약과 연결 |
| 등장 초기 대기 | 원본 staging에서 중첩 차량을 허용하는 예외 존재 | 아직 진입하지 않은 차량은 가상 pending으로 두고 출발 지연 별도 집계 |

팀원 코드도 단순히 결과에 시간을 더하는 것은 아니며 이동 중 상태와 예약을 구현했다. 다만 고정 tick에서 회전과 이동을 하나의 이동기간으로 합산하므로, 별도 회전 단계와 전진 단계의 기하학적 움직임을 재현한 모델이라고 해석하지 않는다. 속도1.0m/s인 일부 설정은 정확히0.1초의 배수가 되어 양자화가 드러나지 않지만, 새0.8m/s에서1.875초는1.9초로 올림된다. 0.1초를 없애는 대신 시각화 간격으로 분리한다. 고정 간격 방식도 충분히 검증하면 사용할 수 있고, 이벤트 방식이 자동으로 공정성을 보장하지 않는다.

## 공정성 및 알고리즘 이름에 대한 주의

기존 rware/fcfs_cross_simulation.py의 Git blob은 c09ada03fc8f849fbd05b0d28e4f44320db4e7dc로 우리가 검토한 예전 코드와 동일하다. 그 코드에서 FCFS는 맨 앞 차량이 호환되지 않으면 반환하지만, 가중치 정책은 compatible 후보를 먼저 골라 점수를 매긴다. FixedQueueModel은 중복 등록만 고치며 이 진입 자격 차이는 바꾸지 않는다. 새 공통 기준에서는 두 정책 모두 같은 실행 가능한 후보 집합을 사용하고, strict FCFS는 필요할 때 규칙 비교용 별도 정책으로 표시해야 한다.

[analyze_step103_holdout.py](https://github.com/poketmon2004-droid/robotic-deadlock-fairness/blob/f7240040f2b88a3a02462c3c78eb68c66a4cc9a0/analyze_step103_holdout.py)의 FairBOModel은 임계 대기시간20/40초를 넘으면 점수에 큰 우선권을 부여한다. FairPSO도 같은 보호 규칙에 PSO가 찾은 가중치를 넣는 방식이다. 이는 'BO/PSO 탐색 알고리즘 개선'과 분리하여 '학습된 점수 정책+장기 대기 보호 규칙'이라고 부르는 것이 정확하다. 실제 구현 시 큰 상수1,000,000 대신 보호 여부·대기시간·기존 점수의 명시적 정렬 우선순위를 권장한다.

[train_realistic_bo_pso.py](https://github.com/poketmon2004-droid/robotic-deadlock-fairness/blob/f7240040f2b88a3a02462c3c78eb68c66a4cc9a0/train_realistic_bo_pso.py)의 Improved_BO/PSO는 total_time + penalty×max_wait로 학습 목적함수를 바꾸는 방식이다. 목적함수 변경 역시 최적화 알고리즘 변경과 별개다. 그 학습에서는 회전 지연0과1m/s를 쓰고 후속 평가에서는 회전/속도 변화를 주므로, 우리 새 물리모델의 기준선을 그 가중치로 대체할 수 없다.

이 저장소에서 Basic은 FIXED_HEURISTIC_WEIGHTS이고, 우리 최근 Basic은 무작위 탐색이다. 표와 범례를 Fixed heuristic / Random search로 구별해야 한다. 장기 대기 보호는 최대 대기와 makespan의 상충관계를 보고하고, makespan을 주목적으로 정한 이번 연구에서 대기만 줄었다고 전체 성능 개선이라고 주장하지 않는다. 대기 균등성 지표는 지연 크기와 함께 보고해야 한다.

## 공통 구현의 진행 순서

1. 중앙 물리 설정 및 정확한 동작시간 함수: 이번에 준비·검증.
2. 이벤트 교통 엔진: 현재 출발/회전/이동 상태 분리, 같은 시각의 완료를 모아서 반영한 뒤 자원 해제→새 도착/출발→후보 수집→동일 자격 필터→선택·예약 순으로 명시한다. 정책별 다른 처리 순서 금지.
3. 공간 검증: 차체 중심/여유 가정에 맞는 점유, 이동의 시작·도착 셀 및 연결 구간, 반대방향 교환, 회전 중 예약, 구역 허가 해제, pending과 실제 출발을 검증한다.
4. 단일 교차로에서 한 차량/두 차량의 이론시간·무충돌·중복 등록·초 단위 대기 계산을 확인한 후 이중/다중 교차로를 같은 엔진에 연결한다. 같은 tick 조건과 같은 규칙으로 고정tick 구현과 맞출 수 있는 단순 회귀 사례도 둔다.
5. 각 레이아웃에서 FCFS/Fixed heuristic/Random/BO/PSO 기준선을 새로 학습한다. 시간 모델이 바뀐 과거 가중치는 후보이며 최적값이 아니다. 작업과 초기 방향·출발 예정시각을 모든 방법에 동일하게 고정한다.
6. 시간 모델, 진입 규칙, 보호 규칙, 변수, 최적화기 효과를 각각 나눠 비교한다. 먼저 기본 진입 조건을 공통화하고, 임계 대기 보호는 on/off로 분리한다. 임계값20/40초를 제조사 요구나 이론적 기아 방지 보장이라고 부르지 않는다.
7. 모든 개발 설정을 고정한 뒤 새 독립 테스트를 실행한다. 이전에 이미 평가한 테스트를 새 모델의 확증용으로 반복 사용하지 않는다.

## 이번에 실제 준비한 것과 아직 하지 않은 것

rware/agv_physical_time.py와 configs/agv_physical_time_v1.json에 통합 설정과 정확한 이동/회전 시간 함수를 추가했다. 90도2.070796초,180도3.641593초,1칸1.875초,4칸7.5초를 검증했다. 시각화 주기를0.1→0.01초로 바꿔도 동작시간이 바뀌지 않는 것을 확인했다. 새 단위검사5개와 기존11개, 총16개가 통과했다.

이 모듈은 설정·동작시간 계산 기반일 뿐 이벤트 교통 엔진이 아니다. 아직 새 모델로 다중 AGV 시뮬레이션, 학습 또는 최종 성능 평가를 실행하지 않았다. 따라서 기존 실험 수치를 초 단위 새 모델 성능으로 바꾸어 제시하지 않는다. 팀원 저장소는 변경하지 않았다.
