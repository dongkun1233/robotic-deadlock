# 공통 진입 조건·물리시간 고정 간격 엔진 v1

사용자 합의에 따라 구현했다. 모든 정책은 같은 진입 가능 후보 집합과 공간·경로 예약을 사용한다. 기존 엄격 FCFS는 `strict_fcfs`라는 별도 규칙 비교로만 둔다. 회전 가감속을 반영하고, 시간 진행은 우선 고정 간격으로 유지하면서 간격 민감도를 확인한다. 이 단계는 엔진 검증이며 최적화나 독립 성능 실험이 아니다.

## 공통 물리 설정

- SHARP XF Type A 차체0.825×0.480m, 차체만 대상으로 함.
- 직진0.8m/s, 가감속 생략. 셀·단일 차로1.5m, 양방향 차로3m.
- 제자리 회전 최대1rad/s, 각가속도/감속도 크기2rad/s², 회전 시작·끝 정지.
- 1칸 이론 이동1.875초,90도 이론 회전2.070796초,180도3.641593초.
- 차체 중심 회전의 외접원 반지름 약0.477238m에 연구 가정 여유0.10m를 더한다. 약1.154476m 이상의 중심간 거리를 요구한다. 실제 제조사 안전거리·회전 중심을 실증한 모델은 아니다.
- 초기 방향은 기본적으로 첫 경로 간선에 정렬한다. 명시적 initial_heading으로 다르게 정할 수 있다.
- 실행 시 레이아웃 객체를 명시적으로 받는다. PhysicalTimeConfig의 layout_rows/cols는 기본 다중 레이아웃 값이며 단일·이중의 실제 구역 수는 각 레이아웃 객체의 1/2개다.

## 구현한 동작과 상태 처리

rware/agv_timed_simulation.py에서 pending/spawned, 대기, 회전 구간, 이동 구간, 완료를 다룬다. 회전과 이동은 별도 시간 구간으로 처리하지만, 보수적인 예약은 둘을 합친 한 셀 이동 작업 전체에 걸쳐 유지한다.

1. 같은 tick에 완료된 모든 이동의 도착을 먼저 반영한다.
2. 공유구역을 벗어나는 이동이 실제로 완료된 차량의 허가·예약을 해제한다. 회전 중 또는 구역 진입 중에는 조기 해제하지 않는다.
3. 출발 예정시각이 지난 차량을 실제 빈 출발 셀에만 배치한다. 같은 출발 셀의 다른 차량은 가상 pending으로 남고 출발 지연을 별도로 기록한다.
4. 허가받지 않았고 실제 대기점에 도착한 차량만 한 번 대기열에 넣는다. 이미 허가받은 차량을 회전 중 재등록하지 않는다.
5. 용량과 현재 점유·도착 예약·로컬 구역 경로+첫 출구 셀 예약을 검사하여 공통 eligible 집합을 만든다.
6. FCFS는 eligible 중 도착순, heuristic은 같은 eligible 중 점수순으로 선택한다. 동률은 대기점 도착시각/ID로 결정한다. strict_fcfs만 전체 큐의 첫 차량이 막히면 다른 가능한 후보를 보내지 않는다.
7. 회전 필요량과 이동시간을 계산하고 각각 ceil(duration/dt) tick으로 올림한다. 회전 완료 후 전진하며 실제 도착 전까지 원래 셀과 도착 셀 예약을 유지한다.

공유구역 용량2는 최대 수용 수이며, 서로 경로가 겹치면 두 대를 동시에 보내지 않는다. 현재 구역의 경로 셀 전체와 첫 출구 셀 예약을 유지하므로 시간 예약으로 같은 경로를 촘촘히 공유하는 방식보다 보수적이다.

현재 직사각 차체는 중심 회전 외접원으로 보수적으로 감싼다. 이동은 인접한 수평/수직 간선만 허용한다. 새 동작을 시작할 때 다른 차량의 진행 중 회전/직진/도착 후 정지 궤적과의 겹치는 시간구간을 나누어, 선형 상대운동의 최소 중심 거리를 해석적으로 검사한다. 이후 새로 시작하는 동작도 같은 검사를 거친다. 점유·예약 소유자와 구역 용량도 검사한다. 이 제한된 모형의 검사이며 모든 실제 AGV 상황의 안전성 보장은 아니다.

## 레이아웃 연결 시 추가한 어댑터

단일·이중 교차로는 기존 corridor8 형상·노드·구역·게이트를 사용한다. 원본 그래프는 기존 경로 생성기가 대기점을 강제로 지나도록 경로를 구성하는 전제이고 일부 도로 연결은 양방향이다. 그 그래프에서 일반 최단경로를 곧바로 사용하면 맞은편 차로로 이동하거나 보호 대기점 없이 core에 접근하는 경로가 가능했다.

그래서 이 공통 엔진에서는 기존 형상을 유지하고 간선을 우측 통행 방향으로 제한하는 메모리상 right_lane_adapter_v1을 적용했다. 원본 레이아웃 파일과 팀원 코드는 수정하지 않았다. 이름에도 어댑터 적용을 표시하며, 원본과 완전히 동일한 경로 생성이라고 주장하지 않는다. 다중 교차로는 기존2×3 유향 그래프를 사용한다. 모든 시작-도착 게이트 조합의 경로 존재와 보호된 진입을 검사했다.

## 시간과 대기 지표의 정의

외부 입력은 모두 초다. 출발 계획도 tick 개수로 재해석하지 않는다. 진단 생성기는 정수 초 단위의 출발 예정시각을 사용하고, 직접 입력한 소수 초도 지원한다. 실제 출발은 예정시각 이후 첫 이용 가능한 tick이다.

- makespan: 시나리오 공통 t=0에서 마지막 AGV가 도착한 시각.
- stationary_wait_s: 출발 후 회전·이동 작업에 속하지 않은 정지 대기 합.
- entry_wait_s: 대기점 도착부터 진입 허가까지의 합(차량별로 별도 제공).
- rotation_s/translation_s: 이론상 회전·직진 소요시간.
- quantization_s: 각 동작 완료를 tick에 올림하면서 추가된 시간. 정지 대기에 섞지 않는다.
- spawn_delay_s: 실제 출발시각-출발 예정시각.

완료 차량마다 실제 출발 후 경과시간 = 정지 대기+이론 회전+이론 이동+양자화 지연인지 검증한다. 미완료 실행의 대기 지표는 관측 종료까지의 검열값이고, 시작된 미완료 작업의 기록된 이론시간은 예약된 작업시간이다. 미완료 makespan은 horizon으로 cap하고 별도 상태를 표시하므로 짧은 조기 정체를 좋은 결과로 보지 않는다. 모든 출발 예정시각이 지난 유한 고정 경로 묶음에서 진행 중 동작과 가능한 새 동작이 전혀 없으면 stalled로 표시한다. 이를 일반적인 전역 교착 방지 정리로 해석하지 않는다.

대기 변수는 초 단위이며 기존 후보별 max 정규화 구조를 유지했다. waiting 정규화의 분모 하한1은 이제1초다. 기존 tick 환경에서 학습한 가중치의 동일한 성능을 가정하지 않는다. maneuver의 기존0/0.5/1 정의 역시 현실성이나 유효성이 자동으로 증명되는 것은 아니다.

## 검사 결과

새 엔진 검사10개와 기존 검사16개를 합친26개가 통과했다. 직진 이론/올림시간,90도/180도 회전, 같은 출발점의 비중첩, 대향 셀 교환 차단, FCFS와 waiting-only 점수의 일치, 공통 eligible 집합, 엄격 FCFS의 별도 동작, 구역 이탈 완료 후 해제, 모든 게이트 경로, 차로에 맞지 않는 외접 범위 거부를 확인했다.

첫 진단에서 예정시각 정수와 결과 소수 표현의 JSON digest 차이가 잡혀, 생성 단계부터 초를 float으로 표준화했다. 최종 진단은 표준화한 새 manifest와 source hash로 처음부터 실행했다. 실패한 중간 점검을 성능 결과로 사용하지 않았다.

## 0.1·0.05·0.01초 민감도

실행 전에 진단 조건과 판정 기준을 protocol_before_run.json에 저장했다. 단일·이중·다중 각각에서8대/출발윈도10초,24대/동시 출발 예정,24대/출발윈도15초와 시드101/202를 사용했다. 고유18개 시나리오×3시간 간격×3정책=162회이며 모든 정책은 같은 시나리오를 재사용한다. heuristic 가중치는 동작 점검용 고정값[1,-0.5,-0.5,-0.5]이고, Basic 학습 결과나 BO/PSO가 아니다.

미완료0, 중복0, 모든 안전 검사 통과.0.1초와0.01초의 완료시간 상대차 최대는1.0613%였으며, 정책 우열의 부호 역전은 없었다(차이0.01초 이하의 동률은 제외). 다중24대/출발윈도15초/시드202의 strict_fcfs는 진입 순서가 달랐다. 따라서 순위가 같아도 궤적이 완전히 같다고 볼 수 없다.

| FCFS 진단 평균(각6개 사례) | dt0.1초 | dt0.05초 | dt0.01초 |
|---|---:|---:|---:|
| 단일 | 136.8667 | 136.8667 | 135.4600 |
| 이중 | 146.1500 | 146.1500 | 144.6467 |
| 다중 | 124.8167 | 124.8167 | 123.5333 |

이 표는 시간 간격 점검이며 레이아웃 간 성능 비교가 아니다. 레이아웃별 작업·경로 길이가 다르다. 이 설정에서는1.875초와2.0708초가0.1초와0.05초 모두 각각1.9초·2.1초로 올림되므로,0.05초로 바꾸는 것만으로 줄어들지 않는 오차가 있다.

여기서 dt 변경은 동작 완료시각의 올림뿐 아니라 의사결정 기회 간격도 함께 바꾼다. 따라서 관측 차이를 순수한 시간 산술 오차 하나로 해석하지 않는다. 정책 간 본 비교에서는 같은 dt와 제어 주기를 고정한다. 제어 주기의 효과만 분리하려면 이후 별도로 고정된 제어 주기와 더 작은 시간 간격을 조합해야 한다.

사전에 둔0.1초 채택 기준은 모든 진단쌍의 완료시간 차이1% 이내 및 순위 역전 없음이었다.1%를 조금 넘어 채택 기준을 통과하지 못했으므로,0.01초를 다음 개발 단계의 잠정 간격으로 둔다.1%는 이 연구의 공학적 허용 기준이고 보편적 정확성 기준은 아니다.

추가로 원래 진단 중24대·시드101의6개 사례를0.005초에서 세 정책으로 실행했다(18회). 미완료0, 안전 검사 통과,0.01초 대비 완료시간 차이 최대0.2631%, 순위 역전0이었다. 이 범위의 안정성을 확인한 것이며 임의의 수요·가중치·임계 정책까지 수렴을 증명하지는 않는다. 주요 알고리즘 비교에서 효과가 이 오차 규모와 비슷하면 더 미세한 간격의 재검증이 필요하다.

## 다음 실험의 범위

이제 새 물리·시간 엔진에서 기준선과 초기 가중치를 다시 학습할 수 있는 기반이 생겼다. 아직 BO/PSO 재학습이나 새로운 변수 ablation은 하지 않았다. 예전 최종 테스트는 재사용하지 않았다. 규칙 효과는 동일 가중치에서 feasible FCFS와 strict FCFS를 따로 비교하고, 변수/최적화기 비교에서는 모든 방법에 동일한 feasible 집합을 적용한다.

팀원의 장기 대기 보호는 별도 진입 규칙 on/off로 두고, 최적화 알고리즘 자체의 개선과 구분한다. 초기 가중치의 선행 탐색 비용과 후속 최적화 예산을 함께 기록한다. 기존 단계 단위 결과와 이번 초 단위 진단을 한 표의 개선율로 섞지 않는다.

재현:

```bash
python -m unittest discover -s tests -v
python scripts/validate_agv_timed_sensitivity.py --output-dir outputs/new_timed_validation
python scripts/validate_agv_timed_finer_clock.py --base-dir outputs/new_timed_validation --output-dir outputs/new_finer_check
```

실제 실행 설정은 configs/agv_timed_v1.json, 원시 결과와 대표 추적은 outputs/agv_timed_validation_v1 및 outputs/agv_timed_finer_clock_v1에 보존한다. 이 설정은 이전 event 계획 설정을 대체하는 고정 시간 간격 엔진 설정이다.
